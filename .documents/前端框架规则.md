## 1. 规则优先级

1. 视觉方向、楼层方向、房间解剖式形态、无障碍与构建验收以
   [`场景设计概述.md`](../首页设计/场景设计概述.md) 为准。
2. 文件放置、目录边界、模块耦合与注册路径以本文档为准。
3. 两者冲突时：视觉与内容可读性优先级最高；在不牺牲前者的前提下，
   目录边界规则必须被遵守。
4. 本文档只规定“前端架构规则”，不改变当前内容文件、导航或 Markdown 写法。

## 2. 现状盘点

### 2.1 技术形态

本项目是单 MkDocs Material 静态站，不是 React / Next / Tailwind 项目：

- 页面由 Python-Markdown 渲染，前端增强靠 `extra_css` 和 `extra_javascript`。
- 入口脚本以经典 IIFE 为主，业务模块使用 ESM，并在需要时动态 `import()`。
- 主题切换依赖 Material 注入的 `data-md-color-scheme="default" | "slate"`。
- 视觉状态通过 CSS 自定义属性（`--nmd-*`、`--md-*`）和根元素上的
  `--nmd-scroll`、`--nmd-sb`、`--mx`、`--my` 传递。
- Three.js 由 npm 声明（`package.json`，当前 `three@0.160.0`），运行时不请求 CDN。
  构建期由 `hooks/vendor_three.py` 把 `node_modules/three` 注入
  `docs/javascripts/vendor/three/`（该目录不入库，见第 3.6 节）。
- Mermaid 目前从 CDN 加载 ESM，这是既有例外；不得再新增运行时 CDN 依赖。

### 3.2 `docs/javascripts/homepage/homepage.js`

它是主页 JS 的**唯一框架入口**，必须遵守：

- 只保留主页生命周期：判断是否处于主页、初始化、清理、`navigation.instant`
  下的 MutationObserver 重初始化。
- 只负责编排同目录 `docs/javascripts/homepage/` 下的模块，不在本文件写具体业务实现。
- 不包含任何 Three.js 场景代码；Three.js 场景由
  `docs/javascripts/three/homepage/convenience-scene.mjs` 独立负责。
- 保持“非首页零开销”：不存在 `.nmd-home` / `.nmd-story` 时不初始化、
  不加载子模块。
- 保持 `prefers-reduced-motion` 降级和无 JS 兜底语义。
- 通过 `scroll-progress.mjs` 写入公共进度变量 `--nmd-scroll`，并广播
  `nmd:scroll` 自定义事件，供 CSS 与 Three.js 镜头共用。

### 3.3 `docs/javascripts/homepage/`

- 存放**除 Three.js 以外**的主页组件。
- 当前已拆分：`viewport-vars.mjs`、`scroll-progress.mjs`、
  `chapter-reveal.mjs`、`spotlight.mjs`、`floor-rail.mjs`。
- 后续可按功能继续拆分，例如打字机、时间线、相册、天气提示等，
  每个文件只负责一件事。
- 模块之间不得互相深耦合；需要共享的状态或工具必须提炼为独立模块，
  不得用全局函数互相调用。
- 允许被同目录的 `homepage.js` 入口动态 `import()`；子模块不得反向
  `import` 入口。
- 非主页逻辑不得放进该目录。

### 3.4 `docs/javascripts/three/`

- `three/homepage/` 存放**主页专属**的 Three.js 场景及其全部组件。
- `convenience-scene.mjs` 是主页 Three.js 场景入口，只负责：
  - 判断 `#convenience-scene` 容器是否存在；
  - 动态加载主页组件；
  - 创建 renderer / scene / 生命周期；
  - 读取 CSS tokens 并接入明暗主题；
  - WebGL 不可用或初始化失败时保留 CSS 降级层。
- `convenience-scene.mjs` 不得实现具体几何、材质、贴图、动画业务；
  这些应落在对应组件中。
- 场景组件按“引擎能力”和“单层内容”两级拆分：
  - 引擎能力：`floor-registry.mjs`、`scroll-map.mjs`、`scene-builder.mjs`、
    `materials.mjs`、`canvas-textures.mjs`、`camera-rig.mjs`、
    `animation-loop.mjs`、`rain-system.mjs`；
  - 单层内容：`floors/<floor-id>.mjs`，F0–F10 每层一篇，
    由 `interior-builder.mjs` 按当前层 ±1 窗口懒加载，滑出窗口即卸载。
- 不得把单层道具、陈列、动效写回 `scene-builder.mjs` 或
  `convenience-scene.mjs`；它们只负责房间群骨架与场景生命周期。
- 子模块通过相对路径加载，不得反向依赖场景入口；需要共享的内容应下沉到
  同目录的共享模块，而不是互相 import。
- 后续其他页面不得 import `three/homepage/` 下的模块。
- 后续多页面共享的 Three.js 代码统一放 `three/common/`，不得塞进
  `three/homepage/`。
- 后续新页面使用 `three/<page>/<page>-scene.mjs` 作为该页场景入口。
  `convenience-scene.mjs` 是历史命名，保留但不作为新页面命名模板。

### 3.5 `docs/stylesheets/`

- `extra.css` 只保留**跨页面 / 全局**内容：
  - 系统字体栈；
  - 全局 `--md-*` 覆盖；
  - 未来确实需要全站复用的视觉 tokens。
- 所有仅用于主页的 `nmd-*` 样式必须从 `extra.css` 移入
  `docs/stylesheets/homepage/`。
- `homepage/homepage.css`：主页布局、文案列、章节动效、楼层编号轨，
  以及明暗两套 `--nmd-*` tokens。
- `homepage/weather.css`：场景画布、CSS 降级房间群、天空 / 地面 / 光晕层，
  以及 Three.js 接管时的 `.is-live` 淡出规则。
- 两个 homepage 样式文件不得重复定义同名 token；需要跨文件共享的
  `--nmd-*` 值只放在一个公共位置（优先 `homepage.css`），
  `weather.css` 只引用，不重定义。
- 所有新增自定义主题 tokens 必须同时维护：

```css
[data-md-color-scheme="default"] { ... }
[data-md-color-scheme="slate"] { ... }
```

- `mindmap.css` 是跨页面样式，保留在 `stylesheets/` 根目录，不得移入
  `homepage/`。

### 3.6 `mkdocs.yml` 注册规则

- 所有直接生效的 CSS / JS 都必须显式注册；不得依赖隐式自动加载。
- 重构完成后，主页 Three.js 入口必须注册为：

```yaml
extra_javascript:
  - javascripts/homepage/homepage.js
  - javascripts/three/homepage/convenience-scene.mjs
```

- 被 `homepage/homepage.js` 或场景入口动态 `import()` 的子模块，不应重复注册为
  `extra_javascript`，避免同一逻辑执行两次。
- `homepage/homepage.js` 应先于主页 Three.js 场景入口注册，确保滚动进度变量先就绪。
- 拆分后的 CSS 至少应注册：

```yaml
extra_css:
  - stylesheets/extra.css
  - stylesheets/homepage/homepage.css
  - stylesheets/homepage/weather.css
  - stylesheets/mindmap.css
```

- 若后续出现其他页面的独立 CSS / JS，按同样规则注册，并只在该页按需加载，
 不污染全站。
- 三方前端库的注入挂在 `hooks/vendor_three.py`（`mkdocs.yml` 的 `hooks:` 项），
 因此构建前置条件是根目录已 `npm install`；Cloudflare 构建命令为
 `pip install -r requirements.txt && npm ci && mkdocs build`。缺 `node_modules/three`
 时构建直接失败，不产出降级站点。
- Cloudflare 上的部署目标二选一，**不要同时指向同一域名**：
  - **Workers（静态资源）**：仓库根 `wrangler.jsonc` 已声明 `assets.directory = ./site`、
    `not_found_handling = "404-page"`；其中 `name` 必须与仪表盘项目名一致，否则会部署到
    另一个 Worker。部署/预览命令保持默认 `npx wrangler deploy` / `npx wrangler preview`。
  - **Pages**：同一套构建命令，输出目录 `site`，不需要 `wrangler.jsonc`。

## 4. 英文文件夹与文件命名规则

本节适用于 `docs/javascripts/` 与 `docs/stylesheets/` 下由本项目维护的英文资源；
`vendor/` 下的第三方文件保持原样，内容型 Markdown 的中文命名不受本节限制。

1. **全部使用小写 ASCII**：不使用中文、全角字符、空格、camelCase、
   PascalCase 或大写缩写。
2. **目录名使用 snake_case**：多单词用下划线连接，例如 `homepage`、
   `common`、`floors`；单词本身保持小写。
3. **文件名使用 kebab-case**：多单词用连字符连接，例如
   `convenience-scene.mjs`、`scene-builder.mjs`、`floor-registry.mjs`、
   `convenience-store.mjs`；
   不使用下划线连接文件名。
4. **扩展名表达模块类型**：ESM 用 `.mjs`，经典脚本用 `.js`，样式用 `.css`；
   不要用 `.js` 去写明确要作为 ESM 的模块。
5. **名字要表达职责**：优先用 `rain-system.mjs`、`camera-rig.mjs` 这类
   能一眼看出职责的名字；避免 `utils.js`、`helpers.js`、`misc.js` 等空泛名字，
   确需共享时也应加上明确领域前缀。
6. **不使用状态或版本后缀**：禁止 `final`、`new`、`old`、`v2`、`tmp`、
   `copy` 等后缀；需要演进时修改内容，不靠复制文件名区分版本。
7. **入口文件可同名**：目录的入口文件允许与目录同名，例如
   `homepage/homepage.js`；除此之外避免目录名与内部文件名重复造成歧义。
8. **新增前先查重**：同一层级不得出现仅在大小写、连字符或下划线上有差异
   的近义文件名；跨平台克隆和构建时这些差异容易互相覆盖。

## 5. 耦合与职责硬规则

1. **入口与业务分离**：入口文件只编排，不写具体业务；业务组件只做单一职责。
2. **依赖单向**：入口可以加载组件，组件不得加载入口；兄弟组件之间不得互相
   import，公共逻辑必须下沉。
3. **JS 不放样式内容**：除非是运行时计算值（如 Canvas 尺寸、粒子坐标、
   CSS 变量数值），不得在 JS 中硬编码视觉；视觉应通过 class 和 CSS tokens。
4. **CSS 不放行为**：状态切换由 JS 控制 class / data 属性，CSS 只描述样式。
5. **主页零开销**：所有主页专属 JS 在非主页页面不得执行初始化，不得引入
   明显性能开销。
6. **`navigation.instant` 兼容**：新增主页 JS 必须考虑内容区被 XHR 替换后
   重新初始化，并在离场时清理事件、观察器和动画句柄。
7. **动效降级**：所有动效必须支持
   `@media (prefers-reduced-motion: reduce)`；JS 初始化前也应读取该偏好。
8. **背景不遮挡**：粒子、背景层、场景画布默认 `pointer-events: none`，
   仅在明确进入交互模式时接管指针。
9. **路径稳定**：不要无谓重命名中文文件名、空格或括号路径；移动文件时
   必须同步 `mkdocs.yml` 与所有相对 import。
10. **不新增外部运行时依赖**：新增前端库必须先用 npm 声明，并把需要发布的文件
    加进 `hooks/vendor_three.py` 的 `FILES` 清单（构建期落到站点内，仓库不提交
    三方源码）；不得新增外部字体。
11. **楼层数据单一来源**：F0–F10 的 id、楼层号、文案 section、标题与
    单层组件加载函数只写在 `floor-registry.mjs`；相机、楼层轨、可见性
    与进度区间都从注册表派生，不得在系统代码里写死层数。
12. **亮暗双主题保持**：默认亮色不可删除，暗色只是并列可选主题；任何新
    场景、材质、灯光或 CSS token 都必须同时给出
    `[data-md-color-scheme="default"]` 与 `[data-md-color-scheme="slate"]`
    两套值，不得让参考图里的暗色舞台取代默认亮色。
