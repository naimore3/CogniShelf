## 1. 设计文档体系：每篇设计文档必须包含的内容

### 1.1 文档怎么组织

首页重设计的设计文档放在 `.documents/首页设计/` 目录下，分两层：

- **本文件（场景设计概述）是总纲**：定义统一模板、整体布局、楼层体系、滚动机制与总计划表。
- **细节设计各归各的子文档**：每个楼层场景、布局滚动系统、封面场景各自一篇，只写自己范围内的细节，不重复总纲内容。

子文档必须与本文件双向引用：子文档开头引用本文件作为上位设计，本文件第 1.3 节的清单登记子文档的状态。

### 1.2 每篇设计文档必须包含的 7 个部分（统一模板）

任何一篇设计文档（含本文件）都必须按以下顺序包含这 7 部分：

| # | 部分 | 必须写清的内容 |
|---|---|---|
| 1 | **文档作用** | 这篇文档负责什么、写给谁看（实现者 / 评审者）、不负责什么。一句话说清定位。 |
| 2 | **描述范围** | `IN`（本文件管哪些页面区块 / 模块 / 文件）与 `OUT`（明确不管哪些，交给哪篇文档）。边界必须无歧义。 |
| 3 | **简略描述** | 300 字内的结论性描述 + 一张总览表。要求：只读这一节也能懂设计意图。 |
| 4 | **详细描述** | 布局尺寸与比例、场景内容清单、镜头与滚动映射参数、动效清单、与上下游文档的接口约定。用表格给出可直接实现的数值，不写形容词堆砌。 |
| 5 | **难点** | 3–8 条。每条写清「难在哪、失败时页面上会是什么现象」。 |
| 6 | **解法** | 与难点**逐条对应**：技术选型、关键实现方向、降级方案、验收方法。 |
| 7 | **相关计划表** | 与本文档相关的实施计划：阶段 / 一句话可见效果 / 主要交付 / 依赖 / 状态（未开始 / 进行中 / 已完成）。 |

**通用要求**（每篇都适用）：

1. 文档头部带版本、更新日期、状态三行。
2. 关键结论附验收证据口径（截图、运行时探针、`mkdocs build` 结果）。
3. 遵守 [前端框架规则.md](../前端框架规则.md) 的全部硬约束（亮色默认、双主题 token、`prefers-reduced-motion` 降级、`navigation.instant` 兼容、中文路径不改名、`mkdocs build` 验收、不用外部字体、粒子层 `pointer-events: none`）。
4. UI 改动完成后至少执行一次 `conda run -n naimore3-docs mkdocs build`。

## 2. 文档作用

**本文件的作用**：作为首页重设计的总纲，回答四个全局问题——

1. 设计文档体系长什么样（第 1 节模板）；
2. 首页整体做成什么样（第 4、5 节：左场景 / 右文案布局、楼层体系、台阶式滚动）；
3. 这件事难在哪、怎么解（第 6、7 节）；
4. 按什么顺序做、每步交付什么（第 8 节计划表）。

**写给谁看**：后续实现者（按计划表逐阶段推进）与评审者（按第 9 节验收清单核对）。

**不负责什么**：任何一个房间内部的道具清单、镜头坐标、动效参数——那些属于各楼层子文档；左右分栏的 CSS 细节与滚动映射的代码方案——属于 `布局与滚动系统.md`。

## 4. 简略描述

把首页做成**一组沿画面右上到左下串成对角链的房间解剖结构**：左侧约 65% 是（近似）满屏的 3D 场景列，右侧约 35% 是同步滚动的文案列。首屏封面展示房间群结构总览；页面采用 threejs-journey.com 式的**分块滚动**（一屏一块 = 一个房间），方向按本站需求设定为**向下**——参考站滚动时内容块向上移出，本站右侧文案块保持常规滚动，「向下」的方向感由左侧场景提供：向下滚，镜头从顶楼 **F10（屋顶露台）** 出发，沿右上—左下对角链逐层下行，进入下一个主题完全不同的微缩房间——汉堡店、图书馆、便利店……全程**纯手动滚动**驱动（滚轮 / 触摸 / 滚动条），无自动播放。楼层**暂定 10 层**（3 层已定、7 层名称已定，后期可能增加），注册表驱动、不写死；右侧文案需扩展到一层一屏。配色**亮暗双模式都包含**：亮色为默认阅读态，暗色以参考站的深紫黑 + violet + teal/coral 为基调。

| 维度 | 判断 |
|---|---|
| 页面位置 | 首页整体（替代现有全宽背景 + 淡入章节结构） |
| 场景形态 | 房间解剖式 diorama：每个楼层是独立房间，房间地面为正方形（宽 = 深），房间之间只以对角顶点相接，右上角接上一间、左下角接下一间，形成一条右上—左下对角链（纪念碑谷式连接） |
| 核心交互 | 分块滚动（一屏一块 = 一个房间）；向下滚 = 左侧场景从顶楼 F10 沿右上—左下对角链逐层下到一楼 F1，右侧文案列同步推进 |
| 滚动驱动 | 纯手动滚动（滚轮 / 触摸 / 滚动条），无自动播放、不劫持滚动 |
| 布局比例 | 桌面 场景 62–68% : 文案 32–38%（左大右小） |
| 楼层数 | 暂定 10 个内容房间（F1–F10）+ 封面 F0；F10 顶楼、F1 底层，注册表驱动，后期可增 |
| 视觉风格 | 节奏与排版借参考站；亮暗双配色都包含（暗色以参考站为基调），亮色为默认阅读态 |
| UI 规则 | 场景内不绘制 HUD / 按钮；首页正文不放按钮 |
| 技术底座 | MkDocs Material + Three.js（本地 vendor）+ 原生 JS |

## 5. 详细描述

### 5.1 参考站实测：threejs-journey.com（2026-10-02）

对 `https://threejs-journey.com/` 做了 1440×900 实测（12 个滚动位置截图 + DOM 探针），可借鉴的结构如下：

| 观察点 | 实测数据 / 行为 | 对本站的意义 |
|---|---|---|
| 顶栏 | `position: fixed`，高 80px；左 logo + 导航，右侧主色胶囊按钮 | 首页顶栏保持 fixed，但不放 CTA 按钮 |
| 首屏分栏 | 左侧文案栏（约 x=110–600，≈37% 宽）+ 右侧 WebGL 画布 `980×820`（x=535 起，约占宽 **68%**、高 91%），两者有重叠 | 「一侧视觉主导、另一侧文字收窄」的比例来源；本站取其镜像（左场景大、右文案小） |
| 编号台阶轨 | 课程章节卡左缘有 `01–07` 竖排编号轨，宽 71px，`position: sticky`（DOM 类名 `.mover`），随滚动逐级停留、指示当前章节 | 「像台阶一样逐级向下」的目录语言，直接借鉴到楼层编号轨 |
| 页面节奏 | 全页 scrollHeight 13702px ≈ 15 屏，按 section 分块推进，**每块内容完全不同**（Basics / Classic techniques / Shaders / Portal Scene …） | 「每个房间内容不一样」的分块原型：房间 = section |
| 滚动方向 | 常规滚动：向下滚时内容块**向上**移出屏幕 | 本站要改造的点：右栏文案保持常规，「向下」的方向感交由左侧场景从顶楼 F10 沿右上—左下对角链下行提供（见 5.6） |
| 排版语言 | 超大粗标题（约 64px）、关键词加粗 + 彩色高亮、小徽章（NEW / free / BEST VALUE）、大圆角卡片 | 右侧文案列的卡片与标题层级照此组织 |
| 配色 | 深紫黑底 + violet 主色 + teal / coral 双点缀 | 「单一主色 + 双点缀」结构直接沿用；暗色模式以此为基调，亮色仍为默认态（见 5.2 / 5.7） |

> 注：实测时该站首屏 3D 内容因资源限流未完成渲染，仅取到画布几何数据；首屏 3D 的具体内容以实机浏览为准，不影响上表结论。

### 5.2 借什么、不借什么

**借**：

1. 分栏比例与「视觉主导、文字收窄」的首屏结构（镜像使用：场景在左）；
2. `01–07` 编号台阶轨 + sticky 指示（本站做成楼层编号轨）；
3. section 分块、逐屏推进的滚动节奏（本站落到「一个房间一屏文案」）——**只借「分块」本身**：参考站滚动时内容块向上移出，本站右栏文案保持常规移动，「向下」的方向语义由左侧场景沿右上—左下对角链下行承担（见 5.6 的方向定义）；
4. 卡片 + 徽章 + 超大标题的排版语言，用于右栏文案；
5. 配色组织方式与暗色基调：「单一主色 + 双点缀」的结构直接沿用；暗色模式以参考站的**深紫黑底 + violet 主色 + teal / coral 点缀**为基调（已确认：亮暗双模式都包含）。

**不借**：

1. CTA 按钮体系 —— 本站首页不放按钮；
2. 外部字体 —— 中文标题沿用系统字体栈 `Georgia, "Noto Serif SC", "Songti SC", "SimSun", serif`；
3. 把暗色当唯一配色 —— 前端框架规则.md 要求默认浅色阅读体验，亮色仍是默认态，暗色是并列可选模式（见 5.7）。

### 5.2.1 场景风格：可滚动的「房间解剖故事书」

**一句话定调**：把每个楼层做成一块可独立观看的「设计师玩具房间」，用糖果色、哑光塑料材质和统一的 3/4 斜上方固定机位串起来；镜头始终从房间左顶角向内看，房间沿画面右上到左下依次对角相接，形成一条每间房都同构、同机位、同开口方向的链式斜向下空间；亮色模式放在浅色摄影棚舞台，暗色模式放在深紫舞台。空间连接借鉴纪念碑谷的非传统几何，材质、灯光与舞台感借鉴 `threejs-journey.com` 的微缩 diorama。

**风格判定**：这不是写实建筑漫游，也不是传统剖面娃娃屋，而是「等距微缩房间 + 玩具模型 + 三渲二绘本」的混合体。它不是一整栋楼，而是一块块同尺寸（地面均为正方形：宽 = 深）、同朝向、同机位的独立房间，沿画面右上到左下以对角顶点串成一条链，避免上一间遮挡下一间开口。参考图的直接判读是：镜头站在房间左顶角外侧、沿该角向房间中心向内看，画面同时看到地板、背墙和右侧墙；房间在画面中留出舞台负空间，不是把房间边缘撑满画面。它也不是照片级材质，而是干净、哑光、略软的塑料 / 黏土 / 树脂质感；室内只放少量焦点道具，像一件被打亮的设计师玩具。

| 维度 | 必须贴住的风格 |
|---|---|

**灯光方案（已确认）**：

- **每房一套独立灯组，不共用全局灯**：每个房间都挂载一套只作用于本房间的灯光，不依赖单一场景级光源打亮整条房间链；邻房灯不串光、不互相影响，房间进入 hold 段时看到的光来自本房间自己的灯。唯一允许的全局光是极低强度的舞台环境底光，只负责抬起暗部、避免死黑，不参与每间房的造型主光。
- **灯位在所有房间里完全相同**：这套灯组按「房间本地坐标」复制到每间房，主光 / 补光 / 轮廓光（若使用）的相对位置、方向、强度、色温与衰减参数逐间一致。也就是说，镜头从上一间走到下一间时，画面里光的方向、软硬、阴影朝向不变，只随房间位置整体平移，不逐层重新布光、不出现某间偏亮、某间偏暗、影子方向跳变。
- **统一灯组模板**：以「宽柔主光 + 低对比补光 + 可选轮廓光 + 环境底光」为同一模板，所有房间照抄同一份灯位数据；其中舞台环境底光可以全局共享，其余灯逐间独立。如某层确需特殊氛围，只允许改动强度、色温或小范围补光，不允许移动主灯位置，避免破坏链的灯光连续性。
- **哑光效果**：房间结构、道具、文字一律走哑光塑料 / 树脂 / 黏土质感——低金属度、低高光、无镜面反射亮点、无脏污贴图；靠宽大柔和的面光和分档 toon 色阶塑形，而不是靠锐利高光。阴影只保留软、浅、短的接触阴影，暗部保持可读、不死黑；发光件（屏幕、灯牌）只作小面积自发光点缀，不产生强烈镜面反光。

**主题映射**：亮色和暗色都是必须保留的一等主题，不能因为参考图是深紫就把整站做成暗色。亮色 = 纸白 / 浅薰衣草灰摄影棚舞台、偏冷白的面光、柔和浅灰接触阴影；暗色 = 深紫黑舞台、偏暖的点光、霓虹边缘光。两套只换舞台底色、灯光与 `--nmd-*` token，不改房间几何、材质语言和镜头关系；切换跟随 Material 的 `data-md-color-scheme` 实时完成，默认进入亮色。

**必须保留的签名**：

1. 房间盒子的“左顶角开口”：去掉顶面、正面和左侧（摄像机从左顶角向内看时最近的三个面），镜头沿左顶角向内看，一眼看到地板、背墙、右侧墙和房间内的少量焦点道具；
2. 双舞台：亮色是干净留白的浅色摄影棚，暗色是干净留白的深紫黑舞台；两套都必须有，不能只有暗色；
3. 糖果色哑光塑料：高明度、低金属、低高光的玩具质感，不是写实 PBR；
4. 链式对角相接：每间房同尺寸同朝向（地面均为正方形 `w = d`），右上角接上一间、左下角接下一间，只在对角顶点处相接，其余不接触；每个房间下方都有实心支柱和底座，整体像一条房间链；
5. 统一固定机位：每间房复用同一个局部机位与同一 `lookAt` 方向，镜头始终从房间左顶角向内看入房间；当前房间占画面约 60–70% 高，邻房只露一个角；镜头沿链平移而不是自由漫游；
6. 软光浅影：阴影是柔和的接触阴影，暗部不死黑；
7. 道具少而有焦点：每间房只保留 1–2 个视觉焦点，其余道具不遮挡房间轮廓。

**统一相机与开口规则（参考图判读）**：

1. **相机固定在左顶角**：每个房间的机位都固定在自身左顶角外侧，视线沿该角向房间中心向内看；不允许从正面平视盒子，也不允许从侧后方看房间外轮廓。
2. **开口取最近三面**：去掉顶面、正面和左侧，也就是摄像机从左顶角向内看时最近的三个面；保留地板、背墙和右侧墙。
3. **每间房一个固定局部机位**：所有楼层共享同一个 `cameraOffset` 与同一个 `lookAt` 局部方向；hold 段机位点不移动、不逐层重新构图，房间内的呼吸与漂浮不带动相机换位。
4. **机位随链平移且落在链的竖直面上**：第 `i` 间房的世界机位 = 第 `i` 间房原点 + 同一个 `cameraOffset`；`cameraOffset` 的水平分量与房间链在地面的投影共线，所以所有机位点都落在过房间群链且垂直于地面的同一竖直面上，机位随链以 `Δx = -w`、`Δy = -h`、`Δz = +d` 同步平移。
5. **取景略后退**：参考图里房间不是满幅特写；当前版本 70–80% 画面高度偏大，目标改为 60–70%（基准 65%），通过沿视线方向增大相机距离实现，FOV 仍保持 30–34°。
6. **统一开口方向与链匹配**：所有房间开口朝向同一固定方位，不逐层旋转；相机视线方向也不随链旋转——链的走向只改变机位点在画面中的位置，不改变每间房的开口朝向和构图。房间链在画面中呈右上—左下走向，当前房间始终处于同一构图位置，上一间和下一间只以边缘 / 角部进入画面。

**禁止项**（后续实现出现即视为跑偏）：

1. 不做整栋楼、连续外立面、写实街景作为主体；
2. 不用写实 PBR 贴图、脏污做旧、高金属度、强反射；
3. 不用纯黑阴影、暗部死黑、重雾气吞掉房间；
4. 不把道具堆满房间，不让每个物体同等重要；
5. 不做自由 FPS / 无约束环绕镜头，不把房间做成普通房间漫游；
6. 不复制参考站的具体道具、品牌、界面、文字与美术资产，只借鉴风格语言。
7. 不做阶梯式左右而下或垂直柱状堆叠，不让上一间房挡住下一间房的开口；也不要把完整邻房一起塞进画面。
8. 不允许房间之间用面或边贴合，只允许「上一间左下角 = 下一间右上角」的顶点相接；本轮不设计、不实现房间之间的连接件。
9. 不允许房间悬空；每间房下方必须有实心支柱与底座承接。

**和纪念碑谷的关系**：借的是“非传统空间连接 + 低多边形大块面 + 安静留白”，不是直接复刻它的配色、关卡、角色或美术资产；本站还要叠加 `threejs-journey.com` 那种深紫舞台、糖果色塑料模型和玩具棚拍感。

**房间排布与开口规则（本次修订）**

房间群在画面上必须读作一条从顶楼 F10 到一楼 F1、沿右上到左下延伸的**链式对角相接房间链**。每间房尺寸、朝向完全相同，且**地面为正方形：宽 = 深（`w = d`），高 `h` 独立；本轮只锁定该比例，不放大房间整体尺寸**。房间盒子的地面边长 `w`、高 `h` 确定后，下一间相对上一间的中心偏移固定：

- `Δx = -w`：下一间中心向左移动一个房间宽；
- `Δy = -h`：下一间中心下降一个房间高；
- `Δz = +d`：下一间中心向相机方向前进一个房间深（正方形地面下 `d = w`，前进距离等于房间宽）。

这样上一间的左下前角恰好等于下一间的右上后角，即每间房右上角接上一间、左下角接下一间，只在角点接触，其他面、边都不接触；房间群不再堆叠成塔。

| 规则 | 建议值 | 说明 |
|---|---|---|
| 顶点接触 | 上一间左下角 = 下一间右上角；其余不接触 | 只允许点接触，不允许面 / 边贴合 |
| 房间比例 | 地面正方形：`w = d`，高 `h` 独立 | 俯视平面为正方形；本轮只锁定比例，不放大房间整体尺寸 |
| 中心偏移 `x` | `Δx = -w` | 每下一间中心向左移动一个房间宽 |
| 中心偏移 `y` | `Δy = -h` | 每下一间中心下降一个房间高 |
| 中心偏移 `z` | `Δz = +d`（`d = w`） | 下一间向相机方向前进一个房间深（等于房间宽），保证上一间左下前角与下一间右上后角只在一点接触 |
| 支柱 | 每间房底部有实心支柱，直落到该房间自己的底座 | 支柱是实心体，不 hollow；只支撑本房间 |
| 底座 | 底座比支柱宽，稳放在舞台地面上 | 每间房一座底座，像链条上每个房间各自的基座 |
| 房间模块 | 保留地板、背墙、右侧墙、白色厚边框；去掉顶面、正面、左侧 | 开口是摄像机从左顶角向内看时最近的三个面 |
| 开口朝向 | 所有房间开口相同，朝向固定相机方位；镜头从左顶角向内看，同时看到地板、背墙、右侧墙 | 不把房间做成只有正面缺口的普通盒子；不允许逐层旋转开口 |
| 统一机位 | 所有房间共享同一 `cameraOffset` 与同一 `lookAt` 局部方向，机位固定在房间左顶角外侧；hold 段机位点固定 | 镜头点随链平移，不逐层重新构图；`cameraOffset` 水平分量沿链的竖直面方向 |
| 当前房间占比 | 画面高度 60–70%，基准 65% | 比当前版本略后退，房间仍是主体但四周保留舞台负空间 |
| 邻房露出 | ≤15% 画面面积，只露一个角 / 一条边框 | 保留链式关联感，但不干扰当前房间 |
| 相机垂直 FOV | 30–34° | 比宽角更接近等距玩具棚拍；禁止鱼眼 / 强透视；不靠加大 FOV 来缩小房间 |
| 相机距离 | 当前房间对角线 1.35–1.55× | 用后退机位缩小房间；再近会撑满画面，再远会带回完整邻房 |
| 连接部分 | 本轮不设计、不写代码 | 房间之间只有顶点接触，不额外做连接件 |

> 说明：① 10 层是暂定数，注册表驱动，增减层数只改配置；② 右侧文案现有 4 章（封面 + 缘起 / 关于我 / 旅程 / 尾声），需扩展为「一房一屏」（约 10+ 屏），绑定在 P0 阶段随文案定稿填入；③ F4–F10 的场景名称已在上面定稿，各层详细设计分别在对应子文档中补齐；系统框架按本总纲先行落地，各层内容在子文档定稿后填充。

**楼层注册表（数据驱动）**：每层一条配置，示意字段——

```js
{
  id: "floor-burger",      // 唯一 id
  floor: 1,                 // 楼层号（F0 = 封面）
  sectionId: "nmd-intro",   // 绑定的文案章节 DOM id
  title: "汉堡店",
  scene: () => import("./scenes/burger.mjs"),   // 场景模块（按需加载）
  hold: [0.18, 0.24],       // 本层 hold（站住看）的滚动进度区间
  descend: [0.24, 0.30],    // 下行过渡区间（沿右上—左下对角链走到下一层）
  camera: { rig: "shared-room-camera" }  // 默认继承统一机位；仅特殊过渡层覆写 descend
}
```

层数 = 注册表长度；相机路径、编号轨、可见性管理全部由注册表生成。`shared-room-camera` 统一提供所有房间共用的 `cameraOffset`、`lookAt` 与 FOV；每层只按 `Δx = -w`、`Δy = -h`、`Δz = +d` 平移机位。**系统里不出现任何写死的「一共 N 层」。**

### 5.6 台阶式滚动机制

**方向与驱动定义（已确认）**：

- **分块结构**：右侧文案一屏一块 = 一个房间（借参考站的分块滚动）；**滚动方向语义为向下**——页面向下滚 = 从顶楼 F10 进入下一层，直到一楼 F1。
- **方向的实现分工**：参考站滚动时内容块向上移出屏幕（常规滚动）；本站右栏文案块**保持常规移动**，「向下」的方向感完全由左侧场景负责——向下滚动时，相机沿右上—左下对角链的延伸方向在世界坐标中逐层下行，画面读作「从顶楼走向底楼」。左右两栏都不做强行逆向位移。
- **纯手动滚动驱动**：只响应滚轮 / 触摸 / 滚动条，进度完全由用户滚动位置决定；无自动播放、无键盘翻页、无全页劫持式接管。分段吸附（scroll snap）默认关闭，是否开启及参数由 `布局与滚动系统.md` 决定。

**目标手感**：向下滚不是匀速漂移，而是「在顶楼 F10 站住看一个房间 → 沿右上—左下对角链落到下一层站住」的阶梯节奏，一直走到一楼 F1；向上滚完全可逆地爬回来。

1. **进度源**：沿用 `homepage.js` 已有的 `--nmd-scroll`（0–1）滚动进度变量，场景与文案共用同一份，不另建滚动监听。
2. **区间映射（不均分）**：每层的进度区间由它绑定的文案 `section` 在页面上的实际 `top / height` 换算而来——文案写多长，层就占多长，**镜头与文案永不脱钩**（难点 1 的解法）。
3. **段内阶梯**：每个区间再拆成两段——
   - **hold 段（约前 65%）**：镜头停在本层统一固定机位（所有房间同一 `cameraOffset` / `lookAt` 局部值），只留呼吸级微动，给「站住看」的停顿；
   - **descend 段（约后 35%）**：镜头从本层门口 → 出门 → 沿右上—左下对角链落到下一层门口；本轮不设计房间之间的连接结构，因此镜头路径只依据房间对角顶点位置生成。速度用 `easeInOutCubic`，起步收尾慢、中间快。
4. **快速滚动防跳**：rAF 主循环里对目标进度做 `lerp` 追赶，快速滚动时镜头平滑追上，不出现硬切或穿墙；区间端点不做瞬移。
5. **楼层可见性与加载窗口**：只渲染当前层 ± 1 层，窗口外的楼层不常驻内存（滑出窗口即卸载，再次进入时按需重建）；下行过程中目标层提前一帧完成初始化，避免落脚瞬间白；±1 窗口内所有主光都提前投射阴影，换层时前后邻房阴影不跳变。
6. **编号轨同步**：当前层编号高亮 + 已走过的层压暗，未到达的层浅色——与文案列章节高亮、场景列渲染三者同源。
7. **文案列动效**：章节卡片沿用现有淡入淡出，与镜头 descend 段错峰（文案先落位、镜头后到达），避免两边同时动造成视觉竞争。
8. **镜头取景**：hold 段所有房间共享同一固定机位，镜头从房间左顶角向内看；当前房间占画面高度 60–70%（基准 65%），垂直 FOV 30–34°，邻房最多只露一个角 / 一条边框（≤15% 画面面积）；descend 段可以略放宽以看到右上角接上一间、左下角接下一间的对角接触关系，但完整邻房不得进入画面。

### 5.7 明暗主题与视觉风格

- **亮暗双模式都包含，两者都是一等公民**（已确认，与「默认亮色」硬约束不冲突）：不能因为参考图是深紫就取消亮色模式。
- **亮色 = 默认阅读态**（前端框架规则.md 硬约束）：浅色摄影棚舞台——纸白 / 浅薰衣草灰底、偏冷白面光、柔和浅灰接触阴影，每层保留主题主色点缀。
- **暗色 = 夜景**：深紫黑舞台 + violet 主色 + teal / coral 双点缀，叠加本站赛博发光点缀，映射到 `--nmd-*` tokens。
- 两套只换舞台底色、灯光与 token，不动房间几何与镜头；切换跟随 Material 的 `data-md-color-scheme` 实时换色，默认进入为亮色。
- 灯光保持「每房一套独立灯组、灯位在所有房间本地坐标里完全一致」：亮暗两套只改灯组强度、色温或补光颜色，不改主灯相对位置；所有房间继续照抄同一份灯位模板，整体材质保持哑光。
- 渲染风格走三渲二路线：`MeshToonMaterial` + 256×1 分档 `gradientMap` + `EdgesGeometry` 描边（注意：分档贴图必须 256×1 灰度、只取红通道）。
- 每层允许一个主题主色，但必须收敛到 `--nmd-floor-*` 前缀的 token，全局主题切换只动根 tokens。
- 赛博朋克点缀（粒子、发光描边、霓虹小面积高光）保留，但遵守：`pointer-events: none`、不遮挡正文、`prefers-reduced-motion` 下可降级（前端框架规则.md 硬约束 8）。

### 5.8 响应式

| 视口 | 布局 |
|---|---|
| ≥1024px | 左右分栏（62–68 : 32–38），场景列 sticky 满屏 |
| <1024px | 上下堆叠：场景列 sticky 在顶部约 55vh，文案列在下方正常滚动；编号轨转为横排或收进角落 |
| 竖屏相机 | 在垂直 30–34° 基础上 FOV +4–6°，机位沿视线继续略微后退；当前房间仍占画面高度 ≥55%，保持镜头从房间左顶角向内看，邻房只露角，不出现完整邻房 |

触屏上竖向手势始终交给页面滚动，场景列不劫持 `touch-action`（若后续引入拖拽交互，`touch-action` 策略由对应子文档处理）。

### 5.9 降级与可访问性

| 情形 | 表现 |
|---|---|
| `prefers-reduced-motion: reduce` | descend 段的逐级插值改为「区间内直接落到本层机位」，楼层内微动效、粒子全部静止；仍可滚动浏览 |
| WebGL 不可用 | 显示 CSS 降级层（房间群剪影分层渐变 + 楼层编号），不白屏；`.is-live` 类控制淡出 |
| `navigation.instant` | MutationObserver 检测场景容器出现/移除；离开首页销毁 renderer、rAF、监听（前端框架规则.md 硬约束 4） |
| 非首页页面 | 不请求 `three.module.js` 与任何场景子模块 |
| 低性能设备 | 像素比 ≤ 2、只渲染 ±1 层、粒子降量、暗色反射可关 |

## 6. 难点

1. **镜头与文案的长度解耦**。文案各章长短不一（「关于我」带 gallery，明显长于尾声）。若进度区间按层数均分，文案滚完了镜头还没下行、或镜头到底了文案还剩一截——两边脱钩，同步感全毁。
2. **楼层数未定，系统必须数据驱动**。层数后面要随文案增减；任何写死「5 层」的相机路径、编号轨、进度除法，改一次文案就全崩。
3. **多层场景的性能预算**。整栋楼全渲染，draw call / 三角形 / 显存随层数线性涨；移动端先卡为敬。失败现象：手机上滚动掉帧、切层卡白。
4. **「沿右上—左下对角链下行」相机路径的平滑性**。对角折线逐级插值很容易在转角抖动、速度不均；快速滚动时若直接跳区间，镜头会穿墙瞬移。同时所有房间必须共用统一机位、统一开口方向和统一取景占比，一旦某层单独调机位或旋转开口，链的连续性会立刻被破坏。
5. **新布局与现有首页动效的冲突**。现有 `homepage.js` 有片头序列、滚动显现、聚光等一整套逻辑，都假设「全宽背景 + 居中内容」；改成左右分栏后类名、进度、容器假设可能互相踩。
6. **`navigation.instant` 下的重复初始化**。场景从首页离开再回来，renderer / rAF / 事件监听若不彻底销毁，会泄漏叠加，越点越卡。
7. **明暗双主题 × 每层主色的 token 管理**。每层一个主色、两套主题 = 2×N 份颜色；散落在各子文档里必然漏配、不一致。
8. **纯程序化资源 + 中文文字**。所有可见内容由几何 / 材质 / 运行时贴图生成，不引入外部 SVG / PNG 美术图，楼层招牌/海报全部 `CanvasTexture` 生成；而验证容器缺中文字体时 canvas 中文会渲染成缺字方框。

## 7. 解法

对应第 6 节逐条：

1. **进度区间由文案 section 的实际位置换算**：每个 `section` 的 `top / height` 归一化到 0–1 得到该层的 `hold + descend` 区间，而不是按层均分；文案长短变化时区间自动重算（resize / instant 导航后重新测量）。→ 文案怎么改，镜头都贴着文案走。
2. **楼层注册表驱动一切**：第 5.5 节的 config 数组是唯一事实来源；相机路径、编号轨、进度区间、可见性全部由注册表生成。加一层 = 加一条配置 + 一个场景模块；所有层默认共享统一 `shared-room-camera`，子文档只填自己的 `hold / descend`，特殊过渡层才覆写 `descend`。
3. **只渲染当前层 ± 1**：层管理器按 active 层维护 ±1 加载窗口——窗口内下层场景模块**动态 `import()` 按需加载**、滑出窗口立即卸载（dispose），落脚前预初始化一帧；窗口内主光统一预投射阴影；成排道具走 `InstancedMesh`；像素比 `Math.min(devicePixelRatio, 2)`；draw call 预算 ≤ 180。
4. **路径与缓动**：`CatmullRomCurve3` / 分段折线插值位置 + `lookAt` 目标 + `fov` 三者同步，`easeInOutCubic`；rAF 主循环对目标进度做 `lerp`（阻尼追赶），区间端点用平滑阶跃函数过渡，禁止瞬移。转角处给相邻对角链节点加切线平滑，消台阶尖角抖动。所有层默认共享 `shared-room-camera` 的 `cameraOffset / lookAt / fov / 开口三面`，只有 descend 过渡路径可按层覆写。验收方式：读运行时相机坐标，快速滚动后采样中间帧须介于首尾之间；逐层探针核对 `cameraOffset / lookAt / 开口三面` 完全一致。
5. **布局隔离**：场景列独立容器（新 id/class 前缀），只消费 `--nmd-scroll` 一个进度变量；现有 `homepage.js` 的片头/显现逻辑保留但作用域限定在文案列；冲突项（全宽背景假设）在 `布局与滚动系统.md` 里逐条列出并改造。
6. **完整的初始化 / 销毁模式**：MutationObserver 监听容器 → 移除时 `renderer.dispose()`、取消 rAF、摘 resize/scroll 监听、清 importmap 状态；验收：反复进出首页 5 次，WebGL context 数量不增长、Console 无报错。
7. **token 两级收敛**：全局主题色只在 `extra.css` 根 tokens 维护两套（亮/暗）；每层主色只允许 `--nmd-floor-<id>-*` 一种前缀，在子文档内成对定义。JS 读 token 时先剥 `alpha`（three 对 `rgba()` 会告警）。夜景材质色不用 CSS 近黑 token 直接当反照率，按层单独给材质色表。
8. **程序化资源工具箱**：几何全部 Box/Extrude/Tube 组合；文字统一 `CanvasTexture`（`colorSpace = SRGBColorSpace`，按画布 ÷ 平面宽高比逐张核对）；中文渲染依赖系统字体栈，验收环境确保 `FONTCONFIG_FILE` 指向带中文的字体目录，确保 canvas 中文不缺字；`git status` 保证 `docs/` 零新增图片文件。

### 8.2 通用规则（每阶段适用）

1. 三种视口都看：桌面 1440×900（亮/暗各一次）、移动 390×844、`prefers-reduced-motion: reduce`。

4. 文件路径、中文文件名不改名；`mkdocs.yml` 的 `nav` 与实际文件保持一致。
5. 环境：一切命令在 Conda 环境 `naimore3-docs` 中执行（`conda run -n naimore3-docs …`）。
