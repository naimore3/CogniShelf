## 1. 问题描述

在 `关系.md` 的「基本派生关系」一节中，源码里 `例：` 两条本应作为「逆关系」的**子节点**（嵌套列表）：

```markdown
2. **逆关系（inverse）$R^{-1}$**：$R^{-1} := \{(b,a) \mid (a,b) \in R\}$，是从 $B$ 到 $A$ 的关系。
   - 例：$<^{-1} = \{(b,a) \mid a < b\} = \{(b,a) \mid b > a\} = {>}$，即"小于"的逆是"大于"。
   - 例：若 $aRb \Leftrightarrow$ "a 吃 b"，则 $bR^{-1}a \Leftrightarrow$ "b 被 a 吃"（被动语态，直观地解释了"逆"的含义）。
```

但构建后的 MkDocs 网站中，两条 `例` 与「补关系」「逆关系」显示为**同一级**，浏览器自动编号为 1、2、3、4。

> 备注：此前看到的乱码（`R:R:=`、`f` 等）与本问题无关——那是把文档内容**直接粘贴**造成的文本变形，源文件本身没有任何字符损坏。

---

## 2. 排查结论（一句话）

**源码内容完好；问题出在 Markdown 渲染方言差异**：MkDocs 的渲染引擎是 **Python-Markdown**，它要求嵌套列表子项**缩进 ≥ 4 空格**；而本文档的嵌套子弹只缩进了 2–3 空格，因此全部被解析成父列表的**同级项**，构建时被拍平。

```python
# <li>子项B</li>     ← 拍平

# <li>第一项<ul>

# <li>子项B</li>
# </ul>
# </li>
# <li>第二项</li>
# </ol>
```

## 4. 根因分析

**MkDocs 使用 Python-Markdown 渲染 Markdown，其嵌套列表规则与 CommonMark（GitHub 用的方言）不同：**

| 规则项 | CommonMark（GitHub） | Python-Markdown（MkDocs） |
|---|---|---|
| 嵌套子项最小缩进 | 2 空格即可（对齐父项内容列） | **统一要求 ≥ 4 空格** |
| 示例 `1. x` + `   - y`（3 空格） | ✅ 嵌套 | ❌ 拍平为同级 |
| 有序列表后混入无序项 `- y` | 视为新列表（`<ul>`） | 并入同一 `<ol>` |

因此：
1. 本文档大概率是在 **GitHub / Typora / Obsidian**（CommonMark 系）上编写和预览的，3 空格缩进在那里显示正常，给人"没问题"的错觉；
2. 一旦经 MkDocs 构建（`mkdocs build` 或 GitHub Actions 部署），Python-Markdown 按自己的规则解析 → 所有 2–3 空格嵌套子弹被拍平，`例` 变成同级编号项（1、2、3、4）；
3. 拓扑排序段更特殊：`- 例（课程先修关系）` 紧跟 `3. 重复直到…` 之后，Python-Markdown 把无序项**直接并入**前面的有序列表，于是该例及其子项被编成第 4–10 号，与算法步骤混在一起。

> 补充：`关系.md` 当前存在**未提交的改动**（`git status` 显示 ` M`），「基本派生关系」这段结构属于工作区中的新内容，尚未经过构建验证——本次问题不是历史提交引入的，而是"以 CommonMark 习惯编写 → 未按 Python-Markdown 规则校验"造成的。

## 6. 修复方案（均经实测验证）

### 方案 A（推荐）：嵌套子弹统一改为 4 空格缩进

对 `关系.md`：
1. 18 处 `   - `（3 空格）→ `    - `（4 空格）；
2. 2 空格嵌套（186–188、303–305、629–630、645–648 行）→ `    - `（4 空格）；
3. 拓扑排序段（645 行附近）的 `- 例（课程先修关系）` 特殊处理——因其紧跟在 `3.` 之后会被并入 `<ol>`，需要二选一：
   - 缩进 4 空格，使其嵌套为「步骤 3」的子项（结构统一，但例子的归属变为步骤 3）；
   - 或改成普通段落/引用块承接例子，再另起 4 空格子弹（保持例子独立于步骤）。

> 4 空格缩进在 CommonMark（GitHub）下同样正常嵌套，不会破坏 GitHub 上的显示，两种方言兼容。

### 方案 B：不用嵌套列表

把 `- 例：…` 改为 `> 例：…`（引用块）或普通段落。改动面大、可读性略降，不推荐作为全局方案，仅适合个别段落。

### 修复后验证方法

```bash

# 检查构建产物中嵌套是否正确：<ul> 应出现在 <li> 内部
grep -o "<li>[^<]*<ul>" site/课程笔记/大二上/离散数学（下）/关系/关系/index.html | wc -l   # 期望 > 0
# 或直接肉眼检查浏览器页面：例 应缩进显示在 逆关系 之下
```

## 7. 附加发现（非本次问题，但值得注意）

1. **乱码与层级无关**：之前看到的 `R:R:=`、`f`、`E` 等乱码是直接复制粘贴导致的文本变形，源文件字符完好。
2. **CI 未锁依赖版本**：`.github/workflows/gh-pages.yml` 仅 `pip install mkdocs mkdocs-material`，本地是 mkdocs 1.6.1 / pymdown-extensions 11.0.1，线上构建版本随时间漂移，存在"本地正常、CI 异常"的隐患，建议固定到 `requirements.txt` 版本并安装。  
   **2026-09-20 更新（已闭环）**：依赖锁定后曾短暂内联进 `environment.yml` 并由 CI 解析安装；**2026-09-23 再更新**：回退为根目录 `requirements.txt` 作为唯一 pip 口径，GitHub Pages workflow 已删除，远端部署改为 Cloudflare Pages（`pip install -r requirements.txt && mkdocs build`）。
3. **MathJax CDN**：站点公式走 `cdn.jsdelivr.net`，大陆网络下偶发加载失败（失败时页面显示原始 `\(...\)` 文本而非公式），如需国内稳定可换 npmmirror 镜像或本地托管。
