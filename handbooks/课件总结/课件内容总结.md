## 附录：仓库 Markdown 渲染注意事项（总结生成时必须遵守）

本仓库笔记使用 **MkDocs（Material 主题，Python-Markdown 引擎）** 构建并部署到 Cloudflare Pages（曾用 GitHub Pages，workflow 已于 2026-09-23 删除）。**Python-Markdown 与 GitHub/Typora 等 CommonMark 渲染器的列表解析规则不同**，以下差异是实际踩坑后总结的（详见 `.documents/MkDocs列表嵌套层级显示问题分析.md`）：

1. **嵌套列表子项必须缩进 ≥4 空格**：
   - 2–3 空格的子项在 MkDocs 构建时会被**拍平为同级列表项**（但在 GitHub 上显示正常，极易漏检）。
   - 正确示例（第二级 4 空格、第三级 8 空格）：
     ```markdown
     1. 步骤一
         - 例：说明
             - 子点1
             - 子点2
     2. 步骤二
     ```
   - 注意：仓库中除 `关系.md` 外仍有约 38 个 md 文件存在 `^   - `（3 空格）问题行，若总结/修改这些文件请一并修正。

2. **有序列表后紧跟 0 缩进的 `- ` 会被并入同一 `<ol>`**：
   - 即使中间有空行，Python-Markdown 仍会把后续无序项并入前一个有序列表示例/说明列表，导致视觉层级错乱。
   - 对策：若某段说明（如“应用”“存在性”）不属于算法步骤本身，**不要用 `- ` 列表**，改为**加粗段落**（如 `**应用**：……`），让 `<ol>` 正常闭合。
   - 已验证：有序列表 + 4 空格缩进的无序子列表可正常嵌套渲染。

3. **公式转义与渲染验证**：
   - 公式中的 `\{` `\}` 等转义在 MkDocs 构建中**原样保留**（正确）；但若用裸 `python3 -m markdown` 渲染（未加载 pymdownx.arithmatex 扩展）会丢失反斜杠，造成误判。

6. **Mermaid mindmap 节点文本禁用半角括号（Syntax error in text）**：
   - **问题**：mermaid 11.16.0 的 mindmap 词法规则中，节点文本 token `NODE_ID` 的正则为 `[^\(\[\n\)\{\}]+`，**显式排除半角 `(` `)` `[` `]` `{` `}`**。节点文本一旦含半角括号（如 `(m,n) 单射 码字`），整块思维导图解析失败，报 `Syntax error in text`（浏览器端渲染时报错，`mkdocs build` 不报）。
   - **注意**：给节点文本加双引号（`"(m,n) ..."`）**并不能**绕过——裸引号会被当作 NODE_ID 的一部分，随后仍撞上 `(` 崩溃（已实测）。`k+1`、`+`、`/`、中文全角括号（`（m,n）`）均安全。
   - **正确方案（已验证，本仓库唯一可靠）**：用 HTML 实体代替半角括号——`&lpar;` 表示 `(`，`&rpar;` 表示 `)`。因本站 mermaid 配置为 `securityLevel: "loose"`，SVG 在 HTML5 解析时会自动把实体解码回 `(` `)`。示例（来自《关系.md》《群和编码.md》）：
     ```mermaid
     mindmap
       root((关系的闭包))
         9.4 关系的闭包
           自反闭包 r&lpar;R&rpar;
           对称闭包 s&lpar;R&rpar;
           传递闭包 t&lpar;R&rpar;
     ```
   - **备选方案**：`id["(m,n) 文本"]`（带 ID 前缀的引号形式，实测可行）或全角括号 `（m,n）`。
   - **排查口诀**：**mindmap 节点里见到半角括号，先换成 `&lpar;`/`&rpar;` 再说**——这是"Syntax error in text"最常见的元凶。
